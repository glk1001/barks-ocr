# One entry per line, either of:
#     SOME LETTERING              ignored wherever it appears
#     <volume> <page> SOME TEXT   ignored only on that page
#
# Matched on letters and digits only, the same normalisation the audit uses, so
# punctuation, case and line breaks do not matter. Blank lines and # are skipped.
#
# This is for lettering that is real but not worth a group. It is NOT for
# suppressing a finding you have not looked at: the audit prints how many
# entries it ignored on every run, so the count stays visible.
#
# Do not "fix" a finding by editing a page's visible_text instead. That field
# records what is actually printed on the page and is true as it stands; an
# ignore belongs here, where it carries a reason.
#
# 2026-09-17: THE ENTRIES BELOW THAT SAY THEY "CANNOT FIRE" WERE WRONG ABOUT WHY.
# Four of them -- 2 009 OP, 13 131 LA, 15 140 DON and 15 140 DU -- were being
# raised by the audit the whole time and the ignore simply could not match them.
# `classify` annotates a finding before it is stored (`[quoted aloud, not boxed]`,
# `[N in the art, M grouped]`) and `ignored()` was normalising that annotated
# string, so no entry could ever equal it. A bare device entry had a second
# problem: `load_ignores` keyed on `normalize`, which reduces `?` to the empty
# string, and then discarded the entry. Both are fixed -- the finding now carries
# the raw lettering alongside its display line, and both sides key on
# `comparable`, which falls back to `device_key`. The containment reasoning in
# those blocks still holds for the `covered` verdict; it was never what stopped
# the ignores working. Measured over 2296 pages: 9 findings moved from reported
# to ignored, none moved the other way.
#
# 2026-09-17, later the same day: the class those four belonged to is now handled
# in code, and NO ignore entry is needed for it. `classify` tested the covering
# group's TYPE before testing whether the lettering was boxed at all, so a
# caption box, a drawn device typed `thought` and a character's noise typed
# `dialogue` -- all three outside `SPEECH_TYPES` -- reported for ever however
# correctly they were grouped. An exact match now ends the question first, and
# the read-aloud check applies only where a sign has no group of its own and

#
